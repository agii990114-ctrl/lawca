# lawca

법무법인 사무원용 송무 AI 에이전트입니다. 법원 문서 PDF를 올리거나 요청을 입력하면 할 일과 기한을 정리하고, 대응 서류 초안까지 만듭니다.

> 현재 상태: 채팅형 화면(Claude·ChatGPT 방식)에서 법원 문서 PDF를 첨부하면 추출 → 송달일 입력 → 기한 계산 → 할 일이 동작합니다. 사무원·변호사·관리자 권한으로 로그인하고, 관리자는 회원 관리 화면에서 계정을 추가·삭제합니다. 글 요청은 LangGraph 라우터가 분류해 기한·사건 조회, 만료일 계산, 서식 작성(확정증명원·송달증명원 신청서, 주소보정서, 사실조회신청서, 집행문부여 신청서)을 처리합니다. 서식에 필요한 정보가 없으면 입력 폼으로 되묻고, 답하면 멈춘 곳에서 이어서 DOCX 초안을 만듭니다. 대화, 첨부 파일, 사건, 문서, 확정한 기한은 PostgreSQL에 저장합니다. 확정한 기한과 기일통지서의 기일, 직접 넣은 일정은 캘린더(월·주)에서 보고, 개인 구독 주소로 휴대폰·Outlook 캘린더에 연결합니다. 기한 목록은 엑셀(CSV)로도 내보냅니다.

## 문서

- [기획서](docs/lawca-기획서.md): 기능 범위, 구조, 데이터 모델, 검증 전략, 로드맵, 리스크
- [사무원 안내](docs/lawca-사무원-안내.md): 현직자 검토용으로 만든 안내문(현재는 사용하지 않음)

## 핵심 원칙

- 기한 계산, 필수 항목 누락 판단, 검증은 LLM이 아닌 코드로 처리합니다.
- 추출값에는 원문 근거를 표시하고, 기한 확정과 제출은 사람이 합니다.
- 로직은 순수 함수에 두고, LangGraph 노드는 이를 호출만 합니다.

## 구조

```
backend/    Python(FastAPI, SQLAlchemy, Alembic, LangGraph 예정). 도메인 로직은 src/lawca/ 아래 순수 함수
frontend/   React + TypeScript(Vite)
docs/       기획서
db/         개발용 DB 초기화 스크립트(docker-compose.yml과 함께)
```

## 개발

백엔드는 [uv](https://docs.astral.sh/uv/), 프론트엔드는 Node.js가 필요합니다.

레포 루트 `.env`에 LLM 설정을 넣습니다(커밋되지 않습니다). `.env.example`을 복사해 쓰면 됩니다.

- **Ollama(로컬)**: `LLM_PROVIDER=ollama`. 이 PC(또는 법인 서버)에서 모델을 돌려서 문서가 밖으로 나가지 않고 사용량 한도가 없습니다. 기본 모델은 `gemma4:e4b`(`ollama pull gemma4:e4b`)입니다. GPU 드라이버가 맞지 않으면 `OLLAMA_NUM_GPU=0`으로 CPU만 씁니다. CPU만 쓰면 요청 분류 15초, 조회 1분, 문서 추출 1분 반 정도 걸립니다.
- **Gemini(클라우드)**: `LLM_PROVIDER=gemini`와 `GEMINI_API=발급받은_키`. 모든 호출(요청 분류·서식 해석·조회·문서 추출)에 `gemini-3.5-flash-lite`를 쓰고, 혼잡하거나 한도에 걸리면 `gemini-3.1-flash-lite`로 넘어갑니다(`.env.example` 참고). 빠르지만 문서가 Google API로 전송되고, 무료 등급은 사용량 한도가 작습니다.

DB(PostgreSQL, Docker)를 띄우고 마이그레이션을 적용합니다. 포트는 5433을 씁니다.

```bash
docker compose up -d --wait
cd backend && uv sync && uv run alembic upgrade head
```

```bash
cd backend && uv run pytest
cd backend && uv run uvicorn lawca.api.app:app --port 8000
cd frontend && npm install && npm run dev
```

- 테스트는 같은 컨테이너의 `lawca_test` 데이터베이스를 씁니다. DB가 없으면 DB 테스트는 건너뜁니다.
- 테이블을 바꾸면 `uv run alembic revision --autogenerate -m "설명"`으로 마이그레이션을 만듭니다. `alembic.ini`는 Windows에서 cp949로 읽히므로 한글을 넣지 않습니다. LangGraph 체크포인트 표(`checkpoints` 등)는 자동 생성 대상에서 빠져 있습니다.

처음 설치하면 관리자 계정을 하나 만듭니다(비밀번호는 입력창에서 받습니다). 그다음 사원 계정은 관리자로 로그인해 **회원 관리** 화면에서 추가·삭제합니다.

```bash
cd backend && uv run python scripts/create_user.py admin 관리자 --role admin
```

브라우저에서 `http://localhost:5173`을 열고 로그인한 뒤, 입력창에 PDF를 끌어다 놓거나 📎로 첨부합니다. 프론트엔드 개발 서버는 `/api` 요청을 백엔드(`localhost:8000`, `LAWCA_API_URL`로 변경 가능)로 넘깁니다.

### 로그인과 권한

| 기능 | 사무원 | 변호사 | 관리자 |
|---|:-:|:-:|:-:|
| 문서 처리·기한 계산·기한 확정·서식 초안·조회 | ✓ | ✓ | |
| 기한 완료·취소·복원·수정 | ✓ | ✓ | |
| 취소한 기한 삭제 | | ✓ | |
| 서식 초안 '검토 완료' 표시 | | ✓ | |
| 회원 관리(계정 추가·삭제·비밀번호 초기화) | | | ✓ |

- 권한은 서버가 검사합니다. 화면의 버튼을 숨기는 것은 편의일 뿐입니다.
- 대화는 본인에게만 보이고, 사건·기한·초안은 법인 전체가 함께 봅니다. 로그인 전의 대화는 주인이 없어 보이지 않습니다.
- 감사 기록(audit_log)에 누가 했는지(아이디)가 남습니다. 계정을 삭제해도 기록을 남기려고 행은 두고 로그인만 막습니다. 삭제한 아이디는 다시 쓸 수 있습니다.
- 비밀번호는 scrypt로 해시해 저장합니다(8자 이상, 글자+숫자). 로그인은 HttpOnly 쿠키 세션(12시간)이고, 같은 아이디로 5번 틀리면 5분 동안 막습니다. 비밀번호를 바꾸거나 초기화하면 그 사용자의 로그인이 모두 끊깁니다.
- 운영(HTTPS)에서는 `.env`에 `COOKIE_SECURE=true`를 넣습니다.

- Gemini를 쓸 때 서버가 혼잡(503)하거나 사용량 한도(429)에 걸리면 예비 모델을 차례로 시도하고, 화면에 실제로 쓴 모델을 표시합니다.
- Gemini를 쓰는 동안에는 실제 의뢰인 문서를 올리지 않습니다. 문서가 Gemini API로 전송됩니다. 동작 확인용 가상 문서는 `backend/tests/fixtures/`에 있습니다(`backend/scripts/make_sample_pdf.py`로 생성).

### 기한 계산 (`lawca.deadlines`)

```python
from datetime import date
from lawca.deadlines import compute_statutory_deadline, compute_designated_deadline, Period, Unit

compute_statutory_deadline("appeal", date(2026, 9, 1)).deadline          # 항소: 2026-09-15
compute_designated_deadline(date(2026, 9, 1), Period(7, Unit.DAY)).deadline  # 보정기간 7일: 2026-09-08
```

- 법정 기간 규칙은 `backend/src/lawca/deadlines/data/rules.toml`에 근거 조문, 조문 발췌, 법령 버전, 확인일과 함께 둡니다.
- 공휴일은 `backend/src/lawca/deadlines/data/kr_holidays.csv`(2024~2028년)에 둡니다. `backend/scripts/generate_holidays.py`로 다시 만들 수 있고, 라이브러리가 모르는 임시공휴일은 직접 추가합니다. 데이터가 없는 연도는 계산을 거부합니다.
- 전자소송 간주 송달은 간주 송달일과 초일 산입 여부를 판단하지 않고 경고만 붙입니다.

### 캘린더

- 사이드바의 **캘린더**에서 월·주 단위로 봅니다. 공휴일은 빨간 글씨로 표시합니다(`kr_holidays.csv`).
- 확정한 것만 보입니다: 진행 중인 기한(만료일에 종일 일정), 확정한 기일, 직접 넣은 일정. 완료·취소한 기한과 미확정 기일은 보이지 않습니다.
- 기일통지서를 처리하면 문서에서 읽은 기일(날짜·시각·장소)이 기한 목록의 **대기** 탭에 들어갑니다. 원문과 대조해 확정하면 캘린더에 올라갑니다.
- 직접 일정을 넣을 수 있습니다(법인 전체 공개 또는 나만 보기). 일정을 고치거나 취소하는 것은 만든 사람이나 변호사만 합니다.
- **내 일정**은 내가 확정했거나 만든 기한·일정만 보여 줍니다.
- **휴대폰·Outlook**: 개인 구독 주소(ICS)를 만들어 캘린더 앱에 넣으면 자동으로 따라옵니다. 주소는 한 번만 보여 주고, 다시 만들면 예전 주소는 끊깁니다. Google 캘린더처럼 외부 서버가 가져가는 앱은 lawca가 외부에서 접속 가능한 서버에 있어야 합니다.

### 자료실 (RAG, `lawca.library`)

- 사이드바의 **자료실**에서 과거 서면·서식(PDF·DOCX·TXT)을 올리고 찾습니다. 채팅에서 처리한 법원 문서(글이 있는 PDF)와 lawca가 만든 초안은 자동으로 들어갑니다.
- 글을 문단 단위로 잘라 PostgreSQL에 저장하고, 두 가지로 함께 찾습니다(결과를 RRF로 합침).
  - 키워드: 검색어 낱말의 절반 이상이 들어 있는 조각(pg_trgm). 사건번호·서식 이름처럼 정확히 맞아야 하는 것.
  - 의미: 로컬 Ollama의 `bge-m3` 임베딩(pgvector). 표현이 달라도 비슷한 내용. 문서가 밖으로 나가지 않고 API 사용량도 없습니다.
- 채팅에서 "예전에 쓴 주소보정서 찾아줘"처럼 물으면 조회 에이전트가 자료실을 찾아 원문 조각과 함께 답합니다.
- 키워드는 공백을 뺀 글과 제목까지 비교합니다("사 실 조 회 신 청 서"처럼 띄어 쓴 제목도 "사실조회신청서"로 찾힘). 임베딩에도 제목을 붙입니다.
- 초안은 사건·서식마다 가장 최근 것만 둡니다. 초안 카드의 **최종본 올리기**로 워드에서 고쳐 낸 최종본(DOCX·PDF)을 올리면 자료실에는 초안 대신 최종본이 들어갑니다.
- 검토 전 초안은 검색 순위를 낮춥니다(최종본·검토 완료 초안·직접 올린 서면이 먼저). 결과에 "최종본", "검토 완료 초안", "검토 전 초안"을 표시합니다.
- 기한 목록에서 문서의 사건번호를 고치면 자료실 항목도 고친 사건으로 옮겨 갑니다.
- **서식 작성 때 참고**: 서식에 필요한 정보를 되묻는 카드와 초안 카드에 같은 서식의 과거 서면(최대 3건)을 "참고할 과거 서면"으로 보여 줍니다. 법원 문서와 방금 만든 초안은 빼고, 최종본·검토 완료 초안·직접 올린 서면이 먼저 나옵니다.
- 임베딩 모델: `ollama pull bge-m3`(약 1.2GB). Ollama가 꺼져 있으면 키워드로만 찾히고, 자료 목록의 **다시 색인**으로 나중에 임베딩합니다. `EMBEDDINGS_ENABLED=false`로 끌 수 있습니다.
- 의미 검색 기준(거리 0.52 이하, 가장 가까운 자료와 0.04 이내)은 합성 서면 4건으로 맞춘 값입니다. 실제 자료가 쌓이면 다시 맞춥니다.
- 스캔본 PDF와 HWP는 아직 읽지 못합니다.

### 준비서면 작성과 초안 탭

**채팅에서 작성합니다.** \"준비서면 작성해줘\"라고 하면 다음 순서로 진행합니다.

1. **사건을 묻습니다.** 사건번호를 말했으면 건너뜁니다.
2. **없는 정보만 되묻습니다.** 우리 측(원고·피고)은 한 번 답하면 사건에 기억하고, 변호사에게는 우리 측 주장 메모(한 줄에 한 가지)를 묻습니다.
3. **자료실(RAG)에서 비슷한 과거 문단을 찾습니다.** 메모마다 자료실의 과거 서면에서 비슷한 문단을 하나씩 찾습니다(최종본·검토 완료 초안·직접 올린 서면. 법원 문서와 검토 전 초안은 제외).
4. **본문 초안을 씁니다(변호사만).** 참고 문단의 논리 전개와 표현을 바탕으로 메모를 풀어 쓰되, 사실·금액·날짜·이름·증거는 이 사건 자료(메모, 상대방 서면 요약, 증거 목록, 사건 기록)로 바꿔 씁니다. 사무원이 요청하면 본문이 빈 틀만 만듭니다.
5. **점검하고 저장합니다.** 본문에서 인용한 증거(갑 제N호증)로 입증방법을 채워 DOCX를 만들고, 초안·근거·점검 결과·참고한 문서를 저장합니다.

- **채팅 답변에 \"참고한 문서\" 목록**(제목 링크, 종류, 어느 메모에 대응했는지, 본문에 반영했는지)이 붙고, 초안 카드에도 같은 목록과 문단별 근거·점검 결과가 있습니다.
- **자동 점검**(먼저 볼 곳을 알려 줄 뿐, 초안은 변호사가 검토합니다): 반영되지 않은 메모 줄, 판례 인용, 메모에 없는 법조문, 증거 목록에 없는 증거, 자료에 없는 금액·날짜, **참고 문서에서 베껴 온 이름**, 근거 없는 문단, [인용 확인 필요] 수. 참고 문단을 실제로 살렸는지는 모델의 표시가 아니라 코드가 본문과 겹치는 문장으로 판정합니다.
- **판례를 만들지 않습니다.** 법리 인용이 필요한 곳은 \"[인용 확인 필요]\"로 남깁니다.
- 본문 초안은 그 사건의 가장 최근 상대방 서면 요약을 반박 대상으로 씁니다.
- 모델이 실패해도 틀(본문은 빈칸)은 만듭니다. 상대방 서면 요약은 채팅에 답변서·준비서면 PDF를 올리면 만들어집니다(스캔본은 요약하지 못함).

**사이드바의 \"초안\" 탭**은 작성한 초안(서식과 준비서면)을 사건별로 보는 곳입니다.

- 초안 목록(사건·종류로 거르기)과 상태(검토 전 / 검토 완료 / 최종본), 초안 상세: 내려받기, 최종본 올리기, 검토 완료 표시(변호사), 준비서면의 본문·근거·점검·참고한 문서.
- **판례 후보(국가법령정보센터, 변호사)**: [인용 확인 필요] 자리마다 \"판례 찾기\"로 대법원 판례 후보(판시사항·판결요지·참조조문·원문 링크)를 보고, 원문을 확인한 뒤 \"이 판례 넣기\"로 인용을 넣으면 DOCX가 바로 바뀝니다. 본문에 자리가 없으면 붙여 넣을 문구를 보여 줍니다.
  - 밖으로 보내는 것은 법률 용어 검색어뿐이고(당사자 이름·숫자·증거 표시는 코드가 뺌) 보낸 검색어는 화면과 감사 기록에 남습니다.
  - `.env`에 `LAW_API`(국가법령정보센터 Open API 인증키 OC)가 필요합니다. 키는 화면에 보내지 않습니다.
  - 모든 낱말을 담은 판례만 돌려주므로 낱말을 줄여 가며 넓히고(검색 최대 8번), 로컬 bge-m3로 쟁점과 판시사항·판결요지를 비교해 다시 늘어놓습니다(유사도 0.45 미만은 뺌).
- 각 초안의 **이 사건의 자료**: 받은 문서(상대방 서면 요약 보기), 기한, 증거 목록(갑호증·을호증 번호 관리, 제출일 표시, 상대방 서면 요약의 증거 일괄 추가).
- 테스트용 가상 답변서: `backend/scripts/make_sample_answer.py` → `backend/tests/fixtures/synthetic_answer.pdf`.

### 기한 목록

| 탭 | 보이는 것 | 할 수 있는 것 |
|---|---|---|
| 대기 | 송달일을 넣지 않은 문서, 미확정 기일 | 송달일 입력·기한 확정, 기일 확정·수정, 기한 없음(목록에서 빼기) |
| 진행 중 | 확정한 기한 | 완료, 취소, 기한 수정(송달일·송달 유형·기간), 사건 정보 수정 |
| 완료 | 완료한 기한과 완료 시각 | 복원(진행 중으로) |
| 취소 | 취소한 기한과 취소 시각 | 복원, 삭제(변호사만) |

- 행을 누르면 문서 상세 팝업이 열립니다. 대기·진행 중에서는 팝업에서 고칠 수 있습니다.
- **같은 사건·같은 종류의 기한은 하나만 진행합니다.** 문서를 읽으면 사건번호로 DB를 찾아 이미 진행 중인 기한이 있는지 확인하고, 있으면 채팅에서 새로 확정할 수 없습니다(서버도 409로 막습니다). 종류가 다른 기한(예: 보정기한과 항소기간)은 따로 확정합니다. 완료하면 같은 종류를 다시 확정할 수 있습니다.
- 확정한 기한은 채팅에서 고칠 수 없고 기한 목록에서 고칩니다. 고치면 새 기한을 만들지 않고 서버가 다시 계산하며, 고치기 전 값은 감사 기록에 남습니다.
- 복원도 같은 규칙을 따릅니다. 같은 종류가 진행 중이면 복원할 수 없습니다.
- 삭제는 행을 지우지 않고 어디에도 보이지 않게 합니다(감사 기록 보존).

### 서식 (`lawca.forms`)

- 서식마다 항목(필수 여부, 기본값, 사건에서 가져올 값, 나중에 입력 허용, 기억 여부)을 `backend/src/lawca/forms/data/forms.toml`에 정의합니다.
- DOCX 템플릿은 `backend/scripts/make_form_templates.py`로 만듭니다. 법인이 쓰던 양식으로 바꾸려면 같은 자리표시자(`{{ case_number }}` 등)를 넣은 DOCX로 교체합니다.
- 서식 문구는 공개 양식의 일반적인 구성을 참고했으며 공식 양식과 한 글자씩 대조하지 않았습니다. 제출 전에 전자소송 양식과 비교합니다.
- 되묻기로 멈춘 작업은 PostgreSQL 체크포인터(LangGraph)로 저장되어 서버를 다시 띄워도 이어갈 수 있습니다.

### 추출 평가 (`backend/eval`)

- `eval/make_documents.py`: 가상 사건으로 합성 법원 문서 16건(텍스트 PDF 10, 스캔본 6)과 정답 JSON을 만듭니다. 판결의 변론종결일·선고일, 기일통지서의 작성일·기일처럼 헷갈리기 쉬운 날짜를 함께 넣었습니다.
- `eval/run.py`: 추출 결과를 정답과 항목별로 비교해 `eval/results/`에 보고서(md·json)를 씁니다. 기본은 로컬 Ollama이고, Gemini는 `--provider gemini --allow-api`를 줘야 돌아갑니다.
- 합성 문서는 실제 법원 문서보다 깨끗하므로 수치는 실제 정확도의 상한으로 봅니다.

```bash
cd backend && uv run python eval/run.py --only scan --limit 3
```
