# lawca 안내 — 법무법인 사무원 검토용

2026-09-22

이 문서는 lawca를 만들기 전에 실제로 송무 업무를 하시는 분들께 설계가 맞는지 여쭙기 위해 드리는 안내입니다. 기술 용어 없이 썼고, 마지막에 질문과 부탁을 정리했습니다.

## 1. lawca가 하는 일

lawca는 법원에서 온 문서를 올리면 무엇을 언제까지 해야 하는지 정리해 주고, 대응 서류 초안까지 만들어 주는 사무 보조 도구입니다. 아직 만들기 전이고, 실제 업무와 맞는지 확인받은 뒤에 만들려고 합니다.

| 하는 일 | 예 |
| --- | --- |
| 법원 문서 읽기 | 보정명령 PDF를 올리면 사건번호, 당사자, 명령 내용을 읽어 정리합니다. 읽은 값마다 원문의 어느 부분에서 읽었는지 표시합니다 |
| 기한 계산 | 송달일을 입력하면 보정기한, 항소기한 같은 기한을 계산합니다. 초일불산입과 공휴일을 반영합니다 |
| 할 일 목록 | 문서 종류에 맞춰 준비할 서류와 할 일을 체크리스트로 보여 줍니다 |
| 서식 초안 | 주소보정서, 확정증명원 신청서 같은 서식을 사건 정보로 채워 초안을 만듭니다 |
| 서식·선례 찾기 | 비슷한 과거 서면이나 양식을 찾아 보여 줍니다 |

결과는 모두 초안입니다. 확인하고 제출하는 것은 사람이 합니다. 기한도 사무원이 확인 버튼을 눌러야 확정됩니다.

## 2. 이렇게 씁니다

**상황 1: 주소보정명령이 왔을 때**

1. 전자소송에서 내려받은 보정명령 PDF를 lawca 화면에 끌어다 놓습니다. 다른 설명은 필요 없습니다.
2. lawca가 문서를 읽고 "○○지방법원 2026가단12345 주소보정명령"으로 인식했다고 보여 줍니다. 사건번호나 당사자를 누르면 원문의 해당 위치가 표시되어 맞게 읽었는지 바로 확인할 수 있습니다. 틀리면 그 자리에서 고칩니다.
3. 송달일을 묻습니다. 송달일은 문서에 적혀 있지 않기 때문에 직접 입력하셔야 합니다. 전자소송에서 확인한 날, 간주 송달일, 종이 수령일 중에서 고릅니다.
4. 보정기한과 할 일(주민등록초본 발급, 주소보정서 제출 등)을 보여 줍니다. 기한은 확인 버튼을 누르면 확정되고 캘린더나 엑셀로 내보낼 수 있습니다.
5. [주소보정서 초안 만들기]를 누르면 사건 정보가 채워진 초안을 내려받습니다. 담당 변호사 확인 후 직접 제출하십니다.

**상황 2: 받은 문서 없이 서류를 만들 때**

입력창에 "2026가단12345 사건 확정증명원 신청서 만들어 줘"라고 적습니다. 법원, 당사자, 담당 변호사는 저장된 사건 정보에서 자동으로 채우고, 없는 정보(예: 판결 확정일)만 묻습니다. 답하면 초안이 나옵니다. 한 번 입력한 정보는 사건에 저장되어 다음에는 다시 묻지 않습니다.

**상황 3: 여러 일을 한 번에 맡길 때**

"111 사건 확정증명원 만들고, 222 사건 주소보정서 만들고, 이번 주 기한도 알려 줘"처럼 한꺼번에 적어도 됩니다. lawca는 먼저 "3건으로 이해했습니다"라고 목록을 보여 주고 동시에 진행합니다. 바로 끝난 건은 결과를 먼저 보여 주고, 정보가 부족한 건들은 질문을 한 화면에 모아 묻습니다. 일부만 답해도 되고, 나머지는 나중에 이어서 답할 수 있습니다.

## 3. 할 수 있는 것과 하지 않는 것

| 합니다 | 하지 않습니다 |
| --- | --- |
| 법원 문서를 읽고 핵심 정보를 정리합니다 | 승소 가능성, 항소 여부 같은 법률 판단은 하지 않습니다. 물으면 담당 변호사께 문의하라고 안내합니다 |
| 기한을 계산합니다 | 기한을 마음대로 확정하지 않습니다. 사무원이 확인해야 확정됩니다 |
| 서식 초안을 만듭니다 | 전자소송에 제출하지 않습니다. 제출은 항상 사람이 합니다 |
| 비슷한 과거 서면을 찾아 줍니다 | 판례 리서치는 하지 않습니다 |
| 기한을 캘린더·엑셀로 내보냅니다 | 지금 쓰시는 사건관리 프로그램을 대체하지 않습니다 |
| 모르는 것은 묻습니다 | 빈 정보를 짐작해서 채우지 않습니다. 필수 정보가 비어 있으면 초안을 만들지 않고 묻습니다 |

등기 업무와 개인회생·파산 서류는 지금 계획에 없습니다. 증거 정리(호증 번호 부여, 증거목록 작성)와 제출 전 서면 점검은 다음 단계에 넣을 예정입니다.

## 4. 의뢰인 문서는 어떻게 다루나

- 문서를 읽고 초안을 쓰는 데는 AI 서비스를 씁니다. 이 서비스를 법인 내부 서버에 둘지, 외부 서비스를 쓸지는 법인의 보안 정책과 법적 검토에 따라 정합니다. 이 부분을 누가 결정하는지 알려 주시면 도움이 됩니다.
- 과거 서면 검색용 자료는 법인 내부에서만 처리합니다. 법인의 서면 전체가 외부로 나가는 일은 없습니다.
- 주민등록번호, 계좌번호 같은 값은 외부로 보내기 전에 가릴 수 있습니다.
- 사건별로 접근 권한을 두고, 누가 언제 어떤 문서를 보고 무엇을 바꿨는지 기록이 남습니다.
- AI가 만든 초안에는 "검토 필요" 표시가 붙고, 변호사 승인 여부가 기록됩니다.
- 시범 사용 단계에서는 이름·주소 등을 가린 문서만 씁니다.

## 5. 여쭙고 싶은 것

아래 질문에 답해 주시면 설계를 실제 업무에 맞추는 데 쓰겠습니다. 문서에 바로 적어 주셔도 되고, 만나서 말씀해 주셔도 됩니다. 모두 답하실 필요는 없습니다.

**지금 업무에 대해**

1. 법원 문서를 하루에 몇 건 정도 받으시고, 한 건을 처리하는 데 보통 얼마나 걸리나요?
2. 하루 중 가장 시간이 많이 드는 일은 무엇인가요?
3. 기한은 지금 어떻게 관리하시나요? (사건관리 프로그램, 엑셀, 수첩 등) 프로그램을 쓰신다면 어떤 것인가요?
4. 송달일은 어떻게 확인하시나요? 전자소송에서 문서를 열지 않았을 때는 어떻게 처리하시나요?
5. 가장 자주 만드는 서식 5가지는 무엇인가요?
6. 서식은 한글(HWP)로 만드시나요? 워드(DOCX) 파일로 초안을 받으면 쓰실 수 있나요, 아니면 한글 파일이어야 하나요?
7. 서식을 만들 때 참고할 과거 서면은 어떻게 찾으시나요? 과거 서면은 어떤 형식으로 어디에 보관되어 있나요?
8. 보정명령을 받으면 보통 어떤 순서로 일하시나요? 이 문서 2번의 상황 1과 다른 점이 있나요?

**도구 사용에 대해**

9. 입력창에 글로 요청하는 방식과 버튼·입력란으로 하는 방식 중 어느 쪽이 편하신가요?
10. 사무원이 만든 초안을 변호사님이 확인하는 절차가 지금 어떻게 되어 있나요?
11. 이 도구가 있다면 가장 먼저 맡기고 싶은 일은 무엇인가요?
12. 이 문서 1번의 기능 중 없어도 되는 것이나 빠진 것이 있나요?

**우려에 대해**

13. 의뢰인 문서를 AI 서비스로 보내는 것에 대해 법인의 입장이나 규정이 있나요? 이런 결정은 누가 하시나요?
14. 이런 도구를 쓸 때 가장 걱정되는 점은 무엇인가요?

## 6. 부탁드리는 것

가능한 범위에서만 부탁드립니다. 특히 샘플 문서가 있어야 문서 읽기 정확도를 제대로 재볼 수 있습니다.

| 부탁 | 내용 | 쓰임새 |
| --- | --- | --- |
| 샘플 문서 10건 이상 | 보정명령, 결정문, 판결문, 기일통지서 등 실제로 받으신 문서. 스캔본도 좋습니다 | 문서 읽기 정확도 측정 |
| 자주 쓰는 서식 파일 3~4종 | 주소보정서, 증명원 신청서 등 실제로 쓰시는 양식 | 초안 템플릿 |
| 기간 규칙 표 검수 | 항소 2주, 즉시항고 1주, 지급명령 이의 2주, 답변서 30일, 간주 송달 규칙 등을 표로 만들어 드리면 맞는지 봐 주십시오 | 기한 계산 정확성 |
| 30분 인터뷰 | 5번 질문을 바탕으로 업무 흐름을 듣습니다 | 기능 우선순위 |

**샘플 문서를 주실 때**

- 이름, 주민등록번호, 주소, 연락처, 계좌번호는 검은 펜이나 편집 프로그램으로 가려 주십시오.
- 사건번호는 숫자를 바꿔도 됩니다. 형식(예: 2026가단12345)만 유지되면 충분합니다.
- 법원명, 문서 종류, 날짜, 명령 내용은 그대로 두셔야 합니다. 이 부분을 읽는 것이 핵심이기 때문입니다.
- 스캔 상태가 나쁘거나 도장이 글자를 가린 문서도 일부러 넣어 주시면 더 도움이 됩니다.
- 샘플 문서는 개발과 정확도 측정에만 쓰고, 외부에 공개하지 않습니다.

질문이나 의견은 이 문서 어느 부분에든 댓글로 남겨 주시면 됩니다.
